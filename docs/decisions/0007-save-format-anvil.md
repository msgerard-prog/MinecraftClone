# ADR 0007 — Save format: vanilla Anvil (Java 1.21)

Status: **Proposed** (2026-10-07) — built while the user was away; awaiting confirmation.

## Context
M7 needs worlds that survive a restart. The save format is on the "never change
without asking" list, so the first choice matters: once worlds exist, changing it
needs a migration. No format existed before M7.

## Decision
Use vanilla Java Edition's own layout, from the public format documentation
(minecraft.wiki: Region file format, Chunk format, NBT format, Java Edition level
format):
- `saves/<world>/region/r.<x>.<z>.mca` — Anvil regions (32x32 chunks, 4 KiB sectors,
  zlib-compressed chunk NBT).
- Chunk NBT as Java 1.21: `DataVersion` 3955 (1.21.1, tied to ADR 0002), `Status
  minecraft:full`, sections with `block_states` (local palette of `Name` +
  `Properties`, vanilla long packing), `biomes`, `SkyLight`/`BlockLight`.
- `saves/<world>/level.dat` — gzip NBT with vanilla's key fields, plus a
  `MinecraftClone` compound for engine-specific settings (generator kind) and a
  `MinecraftCloneState` per hotbar item (exact block state).
- Light is saved but recomputed on load.

## Consequences
- It is the format a replica should have; our NBT/region code is testable against
  the published spec (the wiki's hello_world example is a test).
- Vanilla could likely open our worlds (blocks we register use vanilla ids), but
  that is not a goal; heightmaps, entities, block entities, POI files are absent.
- Our generator differs from vanilla's until M8, so terrain generated by the two
  for the same seed differs.
- Implementation: `core/Nbt`, `core/Compression` (stb deflate/inflate),
  `world/RegionFile`, `world/ChunkSerializer`, `world/ChunkStorage`, `world/LevelData`.
